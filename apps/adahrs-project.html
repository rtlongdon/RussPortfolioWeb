ADAHRS Project

An experimental attitude instrument that rides along on my regular flights. It needs no pitot-static connection, and a GPS-aided estimator running live on the hardware tracks roll and pitch to roughly 1° against the primary avionics on a rigid mount. In simulation it holds attitude within a degree or two of that without GPS at all. The current work is making it honest about when it is unsure.

In-flight data comparison

What it is

A minimal, standalone attitude instrument. Scope is deliberately narrow: attitude (pitch/roll) + altitude + vertical speed. The goal is an instrument a good pilot can cross-check against the rest of the panel, and one that tells the truth about when it is unsure. It does not have to be perfect, but it must never be wrong and quiet.

It is also designed to stand alone. There is no connection to the aircraft's pitot-static system, no airspeed sensor, and no magnetometer. GPS improves the solution when it is available, but the instrument is built to keep working when it is not. It is also built on commercial-grade MEMS sensors, the kind found in consumer and industrial electronics, rather than requiring expensive aviation-grade sensor types. Much of the work is getting good results from affordable parts through better data handling and estimation. The system logs its estimator state and raw sensor data so I can compare it against reference avionics after each flight.

Progress to Date

Hardware (ESP32-S3 Firmware)

  • GPS-aided Extended Kalman Filter now drives the unit's main roll and pitch output, replacing the original complementary filter
  • Commercial-grade sensor suite: BMI270 6-DOF IMU (gyro + accel), MS5611 barometer, KY-040 encoder
  • BLE telemetry streaming roll, pitch, altitude, sensor temperatures, and health flags
  • High-rate onboard data logging for offline analysis

Proof-of-concept hardware mounted in the aircraft

Companion App (Android) — Logging and Comparison

  • Real-time BLE receiver: captures hardware roll, pitch, altitude, IMU and barometer telemetry
  • Reference data logger: reads the Dynon avionics stream via UDP
  • Navigation input: GPS position and magnetic heading from tablet sensors, sent to the hardware
  • Comparative CSV export: side-by-side hardware vs. reference data, synchronized and timestamped
  • Attitude status indicator (OK / degraded / fail) driven by the hardware's own health reporting
  • Python analysis and simulator tools: run recorded flights through the estimator to evaluate changes without flying again

How It Has Progressed

  • August 2026 — baseline. The first flight used a simple gyro + accelerometer filter. Roll error was several degrees, and worst in coordinated turns, where the accelerometer cannot tell a banked turn from level flight.
  • September 2026 — GPS-aided estimator. A GPS-aided Extended Kalman Filter ran live on the hardware alongside the original filter. Whole-flight roll error against the Dynon dropped from about 5° to about 1.3° RMS, and the coordinated-turn problem went away.
  • September–October 2026 — more flights, more lessons. Additional flights included a deliberately poor, flexible mount as a stress case. The estimator now drives the unit's output, and a library of recorded flights supports simulation and comparison.
  • Working without GPS. In a simulator driven by recorded flight data, the same approach holds attitude to within a degree or two of the GPS-aided result with GPS withheld entirely, and with no airspeed or pitot-static input. This has been shown in simulation and still needs confirming in live flight. A software directional gyro looks plausible but is not yet proven.
  • Engine RPM from vibration alone. With the aircraft's fixed-pitch propeller, an FFT of the unit's own high-rate vibration data recovers engine RPM with no tachometer connection. Against the engine monitor, the median error was about 6 rpm and roughly 96% of samples landed within 30 rpm. This is one flight on one aircraft, so I treat it as promising rather than general. It is not yet running in the firmware, and a constant-speed propeller would behave differently.

Does the simulator hold up?

The simulator runs the same estimator against recorded flight data, so the no-GPS results above are only worth trusting if it agrees with what the hardware actually does in the air. So far it does, on roll:

Check Simulator Real flight (hardware)
Predicted before the flight (Sep 1 simulation, flown Sep 3) about 1.25° roll RMS 1.30° roll RMS
Same flight, run both ways (Oct 12) 1.21° roll RMS 1.24° roll RMS

Pitch during climbs agrees less closely, so I treat simulated pitch as directional. Simulator settings have been corrected along the way, such as matching the hardware's update rate, and each fix was checked against a second flight.

What I've Learned

  • Clean inputs matter more than clever filtering. Much of the error I chased early on turned out to be vibration and sampling effects in the data feeding the filter, not the filter itself.
  • Mounting matters. The same hardware performs very differently on a rigid mount and a flexible one, so how it is installed is part of the design.
  • Gyro zero drifts with temperature, and not equally on every axis. Understanding and handling that is the largest remaining error source.
  • The barometric altitude carries a constant per-unit offset and a speed-dependent error, as expected with no static port on a minimal instrument.
  • Knowing when you're wrong is as important as being right. An attitude instrument has to detect and announce GPS loss, warm-up, and stalled processing rather than quietly show a plausible but wrong horizon.

Current Phase

The estimator itself is in good shape, so the focus has moved to everything around it: how the unit characterizes temperature effects, how it detects and annunciates degraded conditions, and how repeatable results are across mounts and flights.

Next Steps

  • Characterize and compensate for gyro temperature effects on the bench
  • Confirm GPS-independent operation in live flight, on a documented, repeatable mount over several flights, including deliberate GPS-loss and cold-start cases
  • Verify the degraded-attitude annunciation with simulated faults (GPS loss, stalled processing, sensor disagreement)
  • Refine the sampling path so the best-performing data handling runs in firmware
  • Display integration: RGB attitude display and vertical-speed tape
  • Board and enclosure refinement
